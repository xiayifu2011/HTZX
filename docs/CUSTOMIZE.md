# 完全自定义手册

> **当前版本速览**：80 条事件（35 条限定时段、38 条设定分布、39 条带条件）、
> 16 个社团、32 条社团事件、80 个天赋、14 种结局。

**最常改的三件事**：
- 改颜色 → [1.2 所有文字颜色](#12-所有文字颜色)
- 改概率 → [2.2 分布模式 dist](#23-分布模式-dist这是主要开关)
- 改连锁 → [3.1 raise 挂起](#31-raise--挂起几周内概率放大推荐)

这份文档回答一个问题：**这个游戏里我能改什么，去哪儿改。**

按"改起来有多方便"排序。绝大多数事情**不需要会编程**。

# 二、事件的发生概率

每个事件都能单独控制概率，**全部写在事件那一行**，不用碰引擎。

## 2.1 事件长什么样

打开 `js/07-data-events.js`（通用事件）或 `js/08-data-events-school.js`（学校事件）：

```js
{
  id: "phone", w: 5, t: "手机诱惑",
  c: "自习课上,同桌悄悄把手机塞到你课本下面……",
  opts: [...]
}
```

**加字段就生效**，下面是全部可用字段。

## 2.2 基础权重 `w`

```js
{id: "phone", w: 5, ...}
                 ↑
```

实测（一局 150 周，同一事件出现多少次）：

| 写法 | 出现次数 |
|---|---|
| `w: 2` | 约 4 次 |
| `w: 5`（默认） | 约 7~9 次 |
| `w: 10` | 约 14 次 |

> 全部事件权重加起来约 300，`w: 5` 大约占 1.7%。

## 2.3 分布模式 `dist`（这是主要开关）

| `dist` | 含义 | 一局次数 | 适合什么 |
|---|---|---|---|
| `decay` | **出现后概率下降** | 约 9 次 | 转折、意外、一次性强的 |
| `uniform` | **均匀铺开** | 约 28 次 | 社团、日常循环 |
| `front` | 前期多后期少 | 约 26 次 | 入学、适应期 |
| `back` | 前期少后期多 | 约 41 次 | 初三冲刺 |

```js
{id: "x", w: 5, dist: "uniform", minGap: 4}
```

- `decay` 配 `decay: 0.5`（每次 ×0.5）、`decayFloor: 0.15`（降到 15% 就停）
- `uniform` 配 `minGap`（两次至少隔几周），它决定"均匀"的粒度
- 全局默认值在 `js/02-config.js` 的 `eventDist`

## 2.4 一学期 / 全局最多出现几次

```js
{id: "x", w: 5, maxTimes: 3}   // 一整局最多出现 3 次
{id: "x", w: 5, once: true}    // 一整局只出现 1 次
```

> 注意：`maxTimes` 是**全局上限**（整个三年），不是每学期。
> 想按学期限制，用 `minTerm` / `maxTerm`：
> ```js
> {id: "x", w: 5, minTerm: 2, maxTerm: 3, maxTimes: 2}  // 只在初二，最多 2 次
> ```

学期编号：`0`=初一上　`1`=初一下　`2`=初二上　`3`=初二下　`4`=初三上　`5`=初三下

## 2.5 时间限定：时段 / 季节 / 月份

```js
{id: "x", w: 5, slot: "weekday"}        // 只在周中（住校）
{id: "y", w: 5, slot: "weekend"}        // 只在周末（回家）
{id: "z", w: 5, season: ["秋"]}         // 只在秋天
{id: "p", w: 5, months: [9, 10]}        // 只在 9、10 月
```

季节：**春**（3~5月）**夏**（6~8月）**秋**（9~11月）**冬**（12~2月）

## 2.6 用 `cond` 做任意条件

```js
cond: S => S.prop.悟性 >= 100        // 悟性高才遇到
cond: S => !Talent.have("网瘾")       // 没网瘾才遇到
cond: S => S.week > 60               // 60 周之后
cond: S => S.prop.经济 < 50           // 穷的时候
cond: S => hasFlag("phone_at_school") // 带了手机（标记）
cond: S => S.club === "huadeng"      // 某个社团成员
cond: S => Math.random() < 0.3       // 整体概率打三折
```

## 2.7 全局节奏参数

**文件：`js/02-config.js`**

```js
eventsPerAction: 1,        // 每次行动后必定跟几个事件
maxChainEvents: 2,         // 最多再连锁几个
chainChance: [0.40, 0.20], // 连锁概率，依次递减
maxEventsPerWeek: 4,       // 每周事件总数硬上限
eventResultMode: "popup",  // "popup" 弹窗 / "log" 只写日志（快一倍）
```

**想让一局变短**：`eventResultMode` 改成 `"log"`，再把 `chainChance` 改成 `[0.2, 0.1]`。

# 三、连锁事件与关系链条

这是本作最有意思的部分。有三种做法，区别很大。

## 3.1 `raise` —— 挂起，几周内概率放大（推荐）

**不立刻弹出来**，而是在接下来 N 周里提高它的出现概率。
像真实生活：做了某件事，后果迟早会来，但不知道是哪天。

```js
{
  id: "phone_bring", w: 6, slot: "weekend",
  t: "返校前，桌上的手机",
  opts: [
    {t: "带上，藏好就行",
      run: ["压力 +5"],
      flag: "phone_at_school",
      raise: [
        {id: "phone_check", weeks: 3, mult: 4, slot: "weekday"},
        {id: "dorm_phone_night", weeks: 3, mult: 4, slot: "weekday"}
      ]}
  ]
}
```

参数：

| 参数 | 含义 |
|---|---|
| `id` | 要提高哪个事件的概率（填事件 id） |
| `weeks` | 持续几周 |
| `mult` | 概率放大几倍 |
| `slot` | 顺便给那个时段增加一次机会 |

也可以写成中文指令：

```js
run: ["压力 +5", "挂起 phone_check 3周 4倍"]
```

## 3.2 `next` —— 排队，下一个立刻弹

```js
{t: "追上去看看", run: ["心态 +3"], next: "event_after_school"}
```

本条结束、玩家点完"继续"后，**立刻**弹出指定事件。适合紧密相连的剧情。

## 3.3 标记 `flag` —— 让事件之间"记住"状态

```js
// 第一步：设置标记
{t: "带上手机", run: ["压力 +5"], flag: "phone_at_school"}

// 第二步：只有标记存在时才可能出现
{id: "phone_check", cond: S => hasFlag("phone_at_school"), ...}

// 第三步：后果发生，清掉标记
run: ["标记 phone_banned", "清除标记 phone_at_school"]
```

中文指令：`标记 名字` / `清除标记 名字`

**这就是"一切有迹可循"的实现方式**：先选择带手机，才可能被查到；被抓后标记清除，不会再重复触发。

## 3.4 三个机制怎么选

| 想要的效果 | 用哪个 |
|---|---|
| 后果迟早来，但不确定哪天 | `raise` |
| 剧情紧接着发生 | `next` |
| 后续事件是否**可能**发生，取决于之前的选择 | `flag` + `cond` |
| 只是提高某个事件的长期频率 | `dist` + `w` |

**真实的手机链条就是三者组合**：`flag` 决定能不能出现 → `raise` 决定何时高概率 → `cond` 做最终守门。

# 四、选项与结果分支

## 4.1 选项的固定结果

```js
{
  t: "咬牙跑完",                    // 选项文字
  sub: "很累，但值得",               // 下面的小字（可选）
  run: ["健康 +5", "计数 运动", "提示 你跑完了全程。!good"]
}
```

## 4.2 中文指令表（run 里能写什么）

| 类型 | 写法 |
|---|---|
| 改属性 | `"心态 +6"` `"健康 -8"` `"压力 -2"` `"经济 +200"` |
| 可用属性 | 心态 经济 健康 效率 悟性 社交 压力 **亲情** |
| 加学力 | `"学力 数学 +25"` `"学力 最弱 +60"` `"全科 +12%"` |
| 计数 | `"计数 运动"` `"计数 读书"` `"计数 拒绝诱惑"` |
| 给天赋 | `"天赋 钢筋铁骨"` `"概率 0.35 天赋 豪"` |
| 写提示 | `"提示 你跑得飞快！"` |
| 提示染色 | `!good` 绿色 / `"!bad"` 红色 / `"!sys"` 蓝色 |
| 学习增益 | `"学习加成 +20% 2周"` |
| 学习减益 | `"学习减益 -30% 2周"` |
| 标记 | `"标记 phone_at_school"` `"清除标记 phone_at_school"` |
| 挂起 | `"挂起 phone_check 3周 4倍"` |

## 4.3 条件分支 `branch`（同一选项多种结果）

```js
{t: "报名试试", run: ["压力 +6", "健康 -3"],
  branch: [
    {cond: S => S.prop.悟性 >= 110 && S.score > 400,
      run: ["悟性 +10", "学习加成 +25% 2周"],
      say: "选拔考你排进了前二十。", cls: "good"},
    {cond: S => S.prop.悟性 >= 95,
      run: ["悟性 +7", "学习加成 +18% 2周"],
      say: "你勉强过了线。", cls: "good"},
    {run: ["悟性 +3", "心态 -4"],
      say: "选拔考你没做完。", cls: "bad"}     // 没写 cond = 兜底
  ]}
```

规则：
- `run` 先执行，**然后**按顺序判断 `branch`
- 命中**第一个** `cond` 为真的分支就停止
- 最后一条不写 `cond` 就是兜底，一定要留一条

现成例子：`js/08-data-events-school.js` 的「五大学科竞赛选拔」。

## 4.4 选项的显示门槛

```js
{t: "只有悟性高才看得见", cond: S => S.prop.悟性 >= 120, run: [...]}
```

不满足条件的选项会**变灰且完全不可点**（没有动效）。

## 5.2 一周的时段结构

**文件：`js/02-config.js` → `week`**

```js
week: {
  // 一周的时间顺序固定为：周中 → 周三社团课 → 周末
  // 数字 = 该时段给几次行动机会；填 0 就是不出现
```

## 6.2 抢社团的时机与规则

- **只有上学期**开放：初一上、初二上、初三上（term 0 / 2 / 4）
- **窗口是每学期第 3~5 周的周末**
- **整个窗口只弹一次** —— 抢不上，这一年就没有社团
- 每学年上学期可以**重选**，但重选会**清零累计次数**（长期坚持的进度从头算）
- 选「不报了」则这一年不再问

改时机在 `js/16-flow.js` 的 `needClubGrab()`：

```js
if (term % 2 !== 0) return false;      // 只有上学期（去掉这行 = 每学期都能抢）
if (wit < 3 || wit > 5) return false;  // 第 3~5 周
if (S.slot !== "weekend") return false;
```

## 6.3 社团活动只在周三

时段顺序固定为 **周中 → 周三社团课 → 周末**。

- 社团事件全部 `slot: "clubday"`，**只在周三社团课出现**，其他时候不会有
- 唯一例外：**花灯社的剧院研学**是走出校园的活动，设为 `slot: "weekend"`
- **没加入社团时不会排「周三社团课」这个时段**（省掉一次空点击）

周三社团课的行动选项和平时不同：

```
🏮 去社团活动   /   📖 留在教室写作业
😴 回宿舍休息   /   👥 找同学玩
```

## 6.4 加一个社团

在 `CLUBS` 数组里加：

```js
{id: "myclub", n: "我的社团", icon: "⭐", cat: "其他", pop: 3,
  desc: "一句话介绍。",
  perk: {悟性: 1, 社交: 1},     // 每周微小加成
  talent: "语感天成"},           // 累计 6 次后可能获得
```

`pop` 是热门度 1~5，越热越难抢（5 约 35%，1 约 85%）。
想让它有外出活动，加 `outdoor: true`（并把那条事件的 `slot` 设成 `"weekend"`）。

## 6.5 给社团配事件

在 `CLUB_EVENTS` 里加：

```js
{id: "cl_myclub_1", w: 5, dist: "uniform", minGap: 4, slot: "clubday",
  cond: S => S.club === "myclub",
  t: "我的社团 · 第一次活动",
  c: "……",
  opts: [
    {t: "认真参与", run: ["悟性 +5", "计数 club", "提示 ……!good"]},
    {t: "摸鱼", run: ["心态 +2", "计数 club", "提示 ……"]},
  ]},
```

三条硬性要求：

1. **`id` 必须以 `cl_社团id_` 开头** —— 系统靠这个前缀找到你的社团事件
2. **`slot: "clubday"`** —— 否则不会在周三社团课出现
3. **`计数 club` 一定要写** —— 否则累计次数不计，拿不到天赋

`minGap: 4` 让两条事件交替出现（约每 2~4 周一次），不会每周都弹同样的。

## 6.6 删一个社团

两步：**删 `CLUBS` 里那一条** + **删 `CLUB_EVENTS` 里 `cl_该id_` 开头的事件**。

只删一半不会崩，但会留下永远触发不到的死数据。

# 九、速查表

## 概率类

| 我想要 | 怎么写 |
|---|---|
| 偶尔出现 | `w: 2` |
| 经常出现 | `w: 8` |
| 出现后减半 | `decay: 0.5` |
| 出现后降到三成 | `decay: 0.3` |
| 均匀铺开 | `dist: "uniform", minGap: 4` |
| 只在前期 | `dist: "front"` |
| 只在后期 | `dist: "back"` |
| 只出现一次 | `once: true` |
| 最多三次 | `maxTimes: 3` |
| 只在初三 | `minTerm: 4` |
| 只在秋天 | `season: ["秋"]` |
| 只在周末 | `slot: "weekend"` |
| 悟性高才遇到 | `cond: S => S.prop.悟性 >= 100` |
| 概率打三折 | `cond: S => Math.random() < 0.3` |

# 十、常见错误

| 症状 | 原因 |
|---|---|
| 改了没变化 | 浏览器缓存，按 Ctrl+F5 强制刷新 |
| 体检报"看不懂这条指令" | 指令拼错，对照第 4.2 节 |
| 事件一直不出现 | 检查 `cond` / `slot` / `season` 是否卡住了 |
| 事件疯狂出现 | `w` 太大，或用了 `uniform` 但没设 `minGap` |
| 改了文档游戏里没变 | 忘了跑 `tools/sync-docs.bat` |
| 存档读不出来 | 新加字段后旧存档缺字段，开新档即可 |
