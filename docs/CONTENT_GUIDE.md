## 第一课：加一条事件

打开文件，你会看到几条已经写好的事件。复制其中一条，改文字即可。

```js
  {
    id: "school_ginkgo", w: 4,
    t: "银杏大道的黄昏",
    c: "放学时你经过学校的银杏大道，满地金黄。",
    opts: [
      {t: "一起捡几片", run: ["心态 +6", "悟性 +2", "提示 你把最完整的一片夹进了课本。"]},
      {t: "匆匆走过",   run: ["压力 -2"]},
    ]
  },
```

逐行解释：

| 写的字 | 意思 |
|---|---|
| `id: "school_ginkgo"` | 事件的唯一编号，**用英文，不能和别的重复** |
| `w: 4` | 出现频率，数字越大越常见（一般写 3~6） |
| `t: "银杏大道的黄昏"` | 弹窗的**标题** |
| `c: "放学时你经过..."` | 弹窗的**正文** |
| `opts: [` | 下面是选项列表 |
| `t: "一起捡几片"` | 选项按钮上的**文字** |
| `run: [...]` | 选了之后**会发生什么** |

## 第二课：写"会发生什么"（指令表）

`run` 后面的方括号里，一条引号一个效果，用逗号隔开。

### 改属性

```
"心态 +6"      "健康 -8"     "压力 -2"
"经济 +200"    "悟性 +3"     "效率 +4"     "社交 +5"
"亲情 +8"      "亲情 -4"
```

八种属性：心态、经济、健康、效率、悟性、社交、压力、**亲情**。
数值范围 0~150（经济不限）。

> **亲情**是家庭关系的度量，只在家庭事件里变动，
> 不在主界面属性栏显示（避免界面太长），在属性栏末尾用一行小字显示。
> 亲情越高，向父母要零花钱越顺利；太低会被念叨甚至拒绝。

### 改成绩

```
"学力 数学 +25"     给数学加 25 分
"学力 最弱 +60"     给当前最差的科目加 60 分
"全科 +12%"         所有科目涨 12%
```

可用科目：语文、数学、英语、物理、化学、历史、政治、生物、地理。

### 记次数（用来解锁成就）

```
"计数 运动"       "计数 志愿者"     "计数 读书"
```

### 给天赋

```
"天赋 钢筋铁骨"              直接获得
"概率 0.35 天赋 豪"          35% 的概率获得
```

### 写一句旁白

```
"提示 你跑得飞快！"          默认白字
"提示 考砸了！!bad"          红字（坏事）
"提示 全班第一！!good"       绿字（好事）
"提示 老师找你谈话。!sys"     蓝字（中性）
```

### 临时加成

```
"学习加成 +20% 2周"      接下来 2 周学习效果提升 20%
"学习减益 -30% 2周"      接下来 2 周学习效果下降 30%
```

## 第四课：常见问题

**Q：我写了但游戏里没出现？**
A：先跑体检脚本（见下）。最常见的原因是逗号漏了或多了。

**Q：我想让某个选项在特定条件下才能选？**
A：这个需要写一点点代码，找技术同学帮忙，或者让 AI 帮你写：
```js
{t: "报名长跑", cond: S => S.prop.健康 >= 100, run: [...]}   // 健康够高才能选
```

**Q：我想加一张配图？**
A：把图片放进 `assets/` 文件夹，然后在事件里加一行：
```js
img: "assets/basketball.jpg",
```

**Q：改坏了网页打不开了怎么办？**
A：换成你备份的 `.bak` 文件。如果没备份，用 `tools/` 里的单文件版重新覆盖。

## ★ 调整单个事件的发生概率

每个事件都可以单独控制出现概率，**不用动引擎代码**，只在该事件那一行加字段。

### 一、基础权重 `w`

```js
{id: "phone", w: 5, t: "手机诱惑", ...}
                 ↑
```

`w` 越大越常见。实测（以「手机诱惑」为例，一局约 150 周）：

| 写法 | 一局平均出现 |
|---|---|
| `w: 2` | 约 4 次 |
| `w: 5`（默认） | 约 7 次 |
| `w: 10` | 约 14 次 |

> 目前全部事件权重加起来约 155，`w: 5` 大约占 3%。

### 二、出现后概率衰减 `decay`

**想让某个事件"出现过就少出现"，用这个。**

```js
{id: "phone", w: 5, decay: 0.5, ...}
                    ↑ 每出现一次，权重乘以 0.5
```

权重变化（w=5 时）：

| 已出现 | decay: 0.5 | decay: 0.3 | 默认（不写） |
|---|---|---|---|
| 0 次 | 5.0 | 5.0 | 5.0 |
| 1 次 | 2.5 | 1.5 | 4.0 |
| 2 次 | 1.25 | 0.45 | 3.0 |
| 3 次 | 0.63 | 0.25 | 2.0 |

一局平均出现次数：`decay: 0.5` 约 3.9 次，`decay: 0.3` 约 3 次，不写约 7 次。

`decay: 0` = 出现一次后不再出现（等同 `once: true`）。

**衰减下限** `decayFloor`（配合 decay 用）：
```js
{id: "phone", w: 5, decay: 0.5, decayFloor: 0.2, ...}
```
上面这行表示：最低降到原权重的 20% 就不再降了（上表会停在 1.0）。

### 三、次数上限

| 字段 | 作用 | 一局平均 |
|---|---|---|
| `once: true` | **一生只出现一次** | 1 次 |
| `maxTimes: 3` | 最多出现 3 次 | 3 次 |

```js
{id: "phone", w: 5, once: true, ...}      // 只出现一次
{id: "phone", w: 5, maxTimes: 3, ...}     // 最多三次
```

### 四、限制出现在哪几个学期

```js
{id: "phone", w: 5, minTerm: 4, ...}   // 最早初三上才出现
{id: "phone", w: 5, maxTerm: 1, ...}   // 初一之后不再出现
{id: "x", w: 5, minTerm: 2, maxTerm: 3} // 只在一整个初二出现
```

学期编号：`0`=初一上　`1`=初一下　`2`=初二上　`3`=初二下　`4`=初三上　`5`=初三下

### 五、用 `cond` 做更复杂的限制

需要写一点点代码，但功能最强：

```js
cond: S => S.prop.悟性 >= 100            // 悟性高才遇到
cond: S => !Talent.have("网瘾")           // 没有网瘾才遇到
cond: S => S.week > 60                   // 60 周之后才遇到
cond: S => S.prop.经济 < 50              // 穷的时候才遇到
cond: S => Math.random() < 0.3           // 每次判定只有 30% 概率进池（等于整体打三折）
```

### 六、组合使用

```js
{
  id: "ht_contest", w: 6,
  minTerm: 4,          // 只在初三
  maxTimes: 2,         // 最多两次
  t: "五大学科竞赛选拔",
  ...
}
```

### 七、常见需求速查

| 我想要的效果 | 怎么写 |
|---|---|
| 偶尔出现 | `w: 2` |
| 经常出现 | `w: 8` |
| 出现一次就基本不再来 | `once: true` |
| 出现后概率减半 | `decay: 0.5` |
| 出现后概率降到三成 | `decay: 0.3` |
| 最多出现两次 | `maxTimes: 2` |
| 只在初三出现 | `minTerm: 4` |
| 只在初一出现 | `maxTerm: 1` |
| 悟性高才遇到 | `cond: S => S.prop.悟性 >= 100` |
| 整体概率打三折 | `cond: S => Math.random() < 0.3` |

### 八、还有两个全局规则（写在引擎里）

1. **同一事件每周最多 1 次** —— 不用担心同一周连着遇到两次
2. **没见过的事件优先** —— 出现不足 2 次的事件会被优先抽到，保证多样性

所以即使把某个事件设成 `w: 10`，它在每个事件都"新鲜"的阶段也不会疯狂刷屏，
因为引擎会先去照顾那些还没出现的事件。

# ★ 时间、时段、季节与事件调度

## 一、游戏里的时间

| 概念 | 说明 |
|---|---|
| 校历 | 上学期 9月→次年1月，下学期 2月→6月，各 25 周，每月 5 周 |
| 季节 | 春 3~5月 · 夏 6~8月 · 秋 9~11月 · 冬 12~2月 |
| 时段 | 一周分 **周中**（🏫 住校）和 **周末**（🏠 回家/自由） |

**时段按先后顺序推进**：一定是先在学校的周中，再是回家的周末。
不会出现"先回家、再回宿舍"这种倒流。

顶栏 📅 会实时显示「月份 · 季节 · 时段」，🎪 显示当前社团。

### 时段数量是动态的

不是固定的"周中1次+周末1次"：

- 基础数量在 `js/02-config.js` 的 `week.slots` 里配
- **如果上一周攒了待触发的后续事件**（`raise`），那个事件指定的时段下周会自动多一次机会
- 上限由 `week.maxExtra` 控制

所以前面埋了周末的伏笔，后面的周末就会自然变长。

---

## 二、把事件绑定到某个时段

```js
{id: "x", w: 5, slot: "weekday", ...}   // 只在周中出现
{id: "y", w: 5, slot: "weekend", ...}   // 只在周末出现
{id: "z", w: 5, ...}                    // 不写 = 两个时段都可能
```

**什么时候要用？**
- 学校里发生的事（上课、查寝、社团结训）→ `weekday`
- 家里或校外发生的事（返校、家长来校、抢社团）→ `weekend`

---

## 三、把事件绑定到季节 / 月份

```js
{id: "a", w: 5, season: ["秋"], ...}          // 只在秋天
{id: "b", w: 5, season: ["春","夏"], ...}     // 春夏都行
{id: "c", w: 5, months: [9, 10], ...}         // 只在 9、10 月
```

现成的四季观景事件可以参考：`ht_season_spring` / `ht_season_summer` / `ht_season_winter`，
以及秋季限定的 `ht_campus_path`（秋日林荫道）。

## 四、控制事件"怎么分布在整个游戏里"

用 `dist`。这是**开关**，几种模式语义完全不同：

| `dist` | 含义 | 适合什么 |
|---|---|---|
| `decay` | 出现一次后概率下降 | 一次性强的事件（转折、意外） |
| `uniform` | 均匀分布，隔一阵子来一次 | 社团、日常循环 |
| `front` | 前期多、后期少 | 入学、适应期 |
| `back` | 前期少、后期多 | 初三冲刺、中考临近 |

```js
{id: "x", w: 5, dist: "uniform", minGap: 4, ...}
                                 ↑ 两次出现至少隔 4 周
```

- `decay` 可以配 `decay: 0.5`（每次 ×0.5）和 `decayFloor: 0.15`（降到 15% 就停）
- `uniform` 建议配 `minGap`，它决定"均匀"的粒度
- 全局默认值在 `js/02-config.js` 的 `eventDist`，单个事件可以覆盖

**实测参考**（一局 150 周，同一事件出现次数）：

| 写法 | 出现次数 |
|---|---|
| `dist: "decay"`（默认） | 约 9 次 |
| `dist: "uniform"` | 约 28 次（平均每 5 周一次） |
| `dist: "front"` | 约 26 次（集中在前期） |
| `dist: "back"` | 约 41 次（集中在后期） |

## 五、后续事件：不必立刻触发

有两种方式，区别很大：

### 方式 A：`raise` —— 挂起，几周内概率放大

**不会立刻弹出来**，而是在接下来 N 周里提高它的出现概率。这更像真实生活：做了某件事，后果迟早会来。

```js
{t: "带上手机", run: ["压力 +5"], flag: "phone_at_school",
  raise: [{id: "phone_check", weeks: 3, mult: 4, slot: "weekday"}]}
```

参数：`id` 事件编号、`weeks` 持续几周、`mult` 概率放大几倍、`slot` 顺便给那个时段加一次机会。

也可以写成中文指令：`挂起 phone_check 3周 4倍`

### 方式 B：`next` —— 排队，下一个就弹

```js
{t: "追上去看看", run: [...], next: "event_after"}
```

本条结束、玩家点完继续后，**立刻**弹出指定事件。适合紧密相连的剧情。

## 六、标记（flag）：让事件之间能"记住"状态

标记是给后续事件读的状态。最典型的用法是手机：

```js
// 周末：要不要带手机
{t: "带上，藏好就行", run: ["压力 +5"], flag: "phone_at_school"}

// 周中：只有带了手机才可能被查到
{id: "phone_check", cond: S => hasFlag("phone_at_school"), ...}

// 被没收后清掉标记
run: ["标记 phone_banned", "清除标记 phone_at_school"]
```

这样"宿舍玩手机被抓"就有迹可循了 —— **先选择带，才可能被抓**。

中文指令：`标记 名字` / `清除标记 名字`

## 七、选项的条件分支

同一个选项，按玩家数值走向不同结果：

```js
{t: "报名试试", run: ["压力 +6", "健康 -3"],
  branch: [
    {cond: S => S.prop.悟性 >= 110 && S.score > 400,
      run: ["悟性 +10", "学习加成 +25% 2周"],
      say: "选拔考你排进了前二十。", cls: "good"},
    {cond: S => S.prop.悟性 >= 95,
      run: ["悟性 +7", "学习加成 +18% 2周"],
      say: "你勉强过了线。", cls: "good"},
    {run: ["悟性 +3", "心态 -4"],
      say: "选拔考你没做完。", cls: "bad"}
  ]}
```

规则：
- `run` 先执行，然后按顺序判断 `branch`
- **命中第一个 `cond` 为真（或没写 `cond`）的分支就停止**
- 最后一条不写 `cond` 就是兜底

现成例子：`js/08-data-events-school.js` 里的「五大学科竞赛选拔」。

## 八、社团系统

16 个社团定义在 `js/05b-data-clubs.js`。

- 初一上第 **1~3 周**的周末触发「抢社团」，6 选 1（含热门与冷门），**可能抢不上**
- `pop` 是热门度 1~5，越热越难抢（篮球社约 35%，志愿服务社约 85%）
- 抢不上可以下周再试，第二次会容易一点
- 入社后每周有社团事件，`dist: "uniform"` + `minGap` 让它们均匀铺开
- 累计参加 6 次后，35% 概率获得社团对应天赋
- 每个社团有每周微小属性加成 `perk`

**加一个新社团**：在 `CLUBS` 数组里加一条，然后在 `CLUB_EVENTS` 里给它配 2 条事件：

```js
{id: "myclub", n: "我的社团", icon: "⭐", cat: "其他", pop: 3,
  desc: "一句话介绍。", perk: {悟性: 1, 社交: 1}, talent: "语感天成"},

// 事件（id 建议 cl_社团id_序号）
{id: "cl_myclub_1", w: 5, dist: "uniform", minGap: 4, slot: "weekday",
  cond: S => S.club === "myclub",
  t: "我的社团 · 第一次活动", c: "……",
  opts: [
    {t: "认真参与", run: ["悟性 +5", "计数 club", "提示 ……!good"]},
    {t: "摸鱼", run: ["心态 +2", "计数 club", "提示 ……"]},
  ]},
```

**注意**：`计数 club` 一定要写，否则累计次数不计，拿不到天赋。

## 隐藏滚动条

默认**隐藏所有滚动条**（弹窗、页面、日志区），但**仍然能正常滚动** —— 只是看不见那条杠。

想恢复显示，打开 `js/02-config.js`，把：

因为滚动条没了，玩家可能不知道内容还有下文，所以加了**底部渐隐提示**：
弹窗内容没看完时，底部会有一道淡渐变，滚到底自动消失。
不想要这个提示就把 `scrollHint` 改成 `false`。

## 弹窗的滚动结构

弹窗本身**不滚动**，只有里面的内容区滚动。
这样右上角的 × 永远固定在弹窗顶部，内容滚到哪儿都能点到，
不会出现"要拉到最顶上才能退出"的情况。
